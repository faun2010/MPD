2. 第三方库：libsacdiso / libdvdaiso 4 高2 中

2.1 libsacdiso（Scarlet Book 解析）

架构：三层结构——sacd_media_t（file/stream 两种介质）→ sacd_disc_t（Scarlet Book TOC 解析）/sacd_dsdiff_t（DFF 解析）继承 sacd_reader_t，外加 sacd_metabase_t（基于 libixml 的 XML 元数据）和 libdstdec（DST 无损解码）。代码为 C 风格 C++，解析大量依赖磁盘上的字节序交换与指针运算。

LIB-1（高）区域 TOC 解析存在系统性越界读，可导致崩溃/信息泄露

src/lib/sacdiso/sacd_disc.cpp:326, 345, 721, 731-732

open() 按 TOC 声称的大小分配缓冲并读入原始数据，随后 read_area_toc() 在没有任何边界校验的情况下信任 TOC 中的一切偏移量：

// 按 TOC 声称的 size 分配，无上限
sb_handle.area[n].area_data = (uint8_t*)malloc(
    sb_handle.master_toc->area_1_toc_size * SACD_LSN_SIZE);
...
while (p < (area_data + area_toc->size * SACD_LSN_SIZE)) {
    ...
    track_ptr = (char*)(p + area_text->track_text_position[i]); // 无界
    track_amount = *track_ptr;          // 越界读
    track_ptr += 4;
    for (uint8_t j = 0; j < track_amount; j++) { ... }

恶意构造的 area_1_toc_size（uint16，最大 65535 扇区 ≈ 128 MB 分配）配合越界的 track_text_position[]、copyright_offset 等偏移，可以在读取时越过分配的堆块（如 sacd_disc.cpp:698-704 的 strlen((char*)area_toc + area_toc->copyright_offset)——一个 16 位无符号偏移可以指向 area_data 之后任意远处，strlen 将一直扫描到下一个 NUL）。同类问题也出现在 read_master_toc() 的 master_text 位置字段（sacd_disc.cpp:624-656）。

建议：所有从 TOC 取出的偏移/数量字段在使用前做 offset + len <= area_size 校验；对 area_toc_size 设置合理上限（实际 SACD 盘 TOC 区远小于 64 扇区）；track_count 校验 ≤ 255（数组 area_track_text[255]、track_start_lsn[255] 的大小）。

LIB-2（高）read_frame() 对扇区头的 packet/frame 计数无上限，栈上数组溢出

src/lib/sacdiso/sacd_disc.cpp:437-464, scarletbook.h:434-435

audio_sector.packet[7] 与 audio_sector.frame[7] 是定长 7 元素数组，而循环上限来自盘面数据中的 3 位字段（0-7）：

for (uint8_t i = 0; i < audio_sector.header.packet_info_count; i++) { // 最大 7，恰好放得下
    ...
if (audio_sector.header.dst_encoded) {
    memcpy(audio_sector.frame, buffer + buffer_offset,
           AUDIO_FRAME_INFO_SIZE * audio_sector.header.frame_info_count);

packet_info_count 为 7 时恰好写满 packet[7]，本身不越界；但 DST 分支的 memcpy(audio_sector.frame, ..., 4 * frame_info_count) 在 frame_info_count == 7 时写 28 字节——frame[7] 每元素 4 字节也是 28，看似安全，但这些计数来自不可信输入且依赖结构体打包假设（#pragma pack + 位域跨编译器布局），一旦 buffer_offset 因恶意 packet_length 累计超过 SACD_LSN_SIZE，后续 memcpy(frame_data, frame.data, frame.size)（sacd_disc.cpp:472-474）在 frame.size 被恶意 packet_length 累计放大后仍受调用方 *frame_size 约束，路径上倒是做了检查（493 行）——真正的问题是 447-458 行的 memcpy 没有对 buffer_offset 做界检查：若 packet_info_count > 0 但扇区数据已被污染，buffer + buffer_offset 可越过 sector_buffer[2064] 读取。此外 509 行 buffer_offset += packet->packet_length（最大 2047）在循环中无总量上限校验，只有 493 行对 DATA_TYPE_AUDIO 分支做了 buffer_offset + packet_length <= SACD_LSN_SIZE 检查，padding/supplementary 类型（503-505 行）直接跳过而不推进校验，offset 可被推到任意大。

建议：在每个 packet 处理前统一校验 buffer_offset + packet_length <= sector_size（对全部 data_type 生效），而非仅 audio 分支。

LIB-3（中）charset_convert() 泄漏 iconv 描述符

src/lib/sacdiso/sacd_disc.cpp:65-86

LIB-4（中）read_area_toc() 解析失败时 area_data 泄漏 + 逻辑不对称

src/lib/sacdiso/sacd_disc.cpp:331-357, 679-681, 706-708

open() 中当 read_blocks_raw 失败时把 area_1_toc_1_start 置零后继续（331-333 行，缓冲保留，后续 close 可释放），但 area_2 失败时却调用 close(); return true;（350-353 行）——两条路径行为不一致。而 read_area_toc() 返回 false（如 679 行 TOC 魔数不符、706 行版本过高）时，已分配的 area_data 既不会被 free 也不会被 close() 释放（close() 只释放 twoch/mulch 索引指向的区域，失败的 area 从未设置索引）——每次打开畸形 ISO 泄漏一块 toc_size * 2048 内存。

建议：read_area_toc 失败时立即 free 该 area_data 并置空；统一两个 area 的失败路径。

LIB-5（低）get_channel_count() 使用了错误的位域名，逻辑脆弱

src/lib/sacdiso/sacd_disc.cpp:88-98

函数读取 channel_bit_2/3 组合返回 5/6 声道，但 scarletbook.h:415-418 中该字节定义为 channel_bit_3:1, channel_bit_2:1, sector_count:5, channel_bit_1:1——channel_bit_1（最低位）从未被检查，声道数 3/4/5 的编码无法区分。该函数当前在文件内无调用者（疑似死代码），若未来启用需先核对 Scarlet Book 规范。

LIB-6（低）sacd_metabase.cpp 文件复制无错误处理、构造函数复制逻辑可疑

LIB-7（低）seek() 的 double 换算与除零风险

src/lib/sacdiso/sacd_disc.cpp:533-536

2.2 libdvdaiso（UDF + DVD-Audio + MLP）

架构：udf/ 实现 DVD ISO 的 UDF 文件系统读取，dvda_* 解析 AUDIO_TS 目录的 IFO/AOB 结构并组织为 zone/track，libmlpdec 是 MLP（Meridian Lossless Packing）解码器，audio_stream 系列做 PCM 流拼接。代码量最大（约 8,000 行），同样为 C 风格解析代码。抽查发现：

LIB-8（高）UDF/IFO 解析普遍缺乏对不可信偏移的界检查

src/lib/dvdaiso/udf/dvd_udf.cpp（全文）, src/lib/dvdaiso/ifo.h, src/lib/dvdaiso/dvda_zone.cpp

与 libsacdiso 同样的模式：UDF 描述符长度、分区映射大小、IFO 表项数量与文件偏移均直接来自镜像内容，解析循环中极少对读取长度与缓冲边界做校验（如 UDFDescriptorTag 长度字段直接用于 memcpy；sector 读取函数对读短的情况多数路径仅返回错误而非清理）。作为解析用户提供的任意 .iso 文件的守护进程组件，这些代码应当被视为攻击面。与 sacdiso 相比，dvdaiso 的 stream_buffer.h 有基本的大小跟踪，但 consumer 侧的越界读依旧普遍。

建议：至少对 UDF descriptor 长度、partition/VOB LBA 范围、IFO 表项索引加集中校验；理想方案是引入一个 BoundsChecker 包装所有原始读取。

LIB-9（低）C/C++ 混编与构建卫生

src/lib/dvdaiso/**（mlpdec.c 为 C89 风格，其余为 C++）

libmlpdec 的 C 代码使用变长局部缓冲和大量手工位操作，风格与 MPD 上游差异大，但作为 vendored 第三方解码器可接受。注意到 DvdaIsoDecoderPlugin.cxx:44-46 手动 include <assert.h>/<stdio.h>/<stdlib.h>，MPD 风格应使用 <cassert> 等或依赖传递包含。

库层评审小结：两个库是历史代码的忠实移植，功能验证充分（29/29 位精确解码），但健壮性从未按"解析不可信输入"标准审过。MPD 上游对外来容器格式的处理（如 dsf、dsdiff 自带插件）都做了系统的边界校验。鉴于个人分支的威胁模型（本地音乐库），风险可接受，但发布二进制 installer（install.sh 分发到他人机器）后建议至少修复 LIB-1/LIB-2/LIB-8。

PLG-1（中）DvdaIsoDecoderPlugin 的 reader 状态不是 thread_local，跨线程共享可变全局

src/decoder/plugins/DvdaIsoDecoderPlugin.cxx:65-68

对比 SacdIsoDecoderPlugin.cxx:64-67 与 DffDecoderPlugin.cxx:63-65 都把同组状态声明为 thread_local 并注释了原因（"Database updates, tag scans and decoders run on different threads"）。dvdaiso 插件漏掉了 thread_local：数据库更新线程扫描目录时 container_update() 会 close/reset 这些全局对象，而解码线程正在用它们播放——use-after-free 竞态。提交说明声称"isolates per-call reader state so a rescan or readpicture cannot disturb the playing track"，对 dvdaiso 并未兑现。

建议：补上 thread_local（并同步 finish() 语义）。这是插解层最应尽快修的一处。

5. ALSA 输出桥接（06d139984）1 低

新增 dsd_to_pcm_bridge/pcm_to_dsd_bridge 两个默认关闭的选项：DAC（如 Shanling UA2 Plus）无法同时切换 DSD/PCM 模式与字时钟时，先以 S16 静音流在目标字速率上播 500ms 并 drain，再以新模式重开设备。实现要点：

  • PlayPcmBridge() 独立打开第二个 ALSA PCM 设备，3 秒超时 + interrupted 检查（持锁窗口极小），AtScopeExit 保证关闭；
  • PreparePcmToDsdBridge() 用新提取的 Alsa::ConfigureHwFormat()（HwSetup.cxx 的干净重构：SetupHw 拆为"协商格式"与"应用参数"两段）探测 native DSD 格式而不落参数；
  • 状态跟踪（last_open_was_native_dsd 等）只在 Open 成功路径更新。

ALSA-1（低）Drain() 中 pcm_export->Reset() 重复调用两次

src/output/plugins/AlsaOutputPlugin.cxx（06d139984 diff，Drain() 末尾）

/* Discard any incomplete DSD export block after draining. */

评价：这是全组提交中工程质量最高的一块：并发处理（check_progress 持锁只查 bool）、资源管理（AtScopeExit/std::exchange）、边界情况（EAGAIN/EINTR/SETUP 状态、n > requested 校验、32768/channels 防零除）都考虑周到，且重构 ConfigureHwFormat 使探测与配置分离的手法正确。22/22 次模式切换实测通过。唯一建议是补一个单元可测的抽象（当前逻辑深嵌在 AlsaOutput 私有方法中）。
